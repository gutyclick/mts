# Country and regional eSIM pages

Each destination has one plan-selection page in English and Spanish. Selection, filtering and ordering remain on the same page. Existing direct plan links reuse it.

One purchase panel contains the radio selector and the selected plan's essentials: allowance, duration, declared network technology, country operators (or regional country count), validity start, device checker and continuation action. These update together for the exact selected variant. Empty results remove the action and selected-plan region. Sorting stays visible; optional GB/day filters sit in a native disclosure. Mobile options use two compact columns and a smaller destination header.

Regional included-country lists can be opened alongside the essentials. Technology disagreements and the supplied fair-use limitation stay visible before continuing. Secondary variant details (exact operator/network table, top-up policy, APN and original plan name) live in one “Technical details and conditions” disclosure inside the same panel. Regional tables retain destination row groups and bounded keyboard-focusable scrolling. Legacy AN coverage and source uncertainties remain qualified. The former separate detail/conditions area below the purchase block is removed.

Below the panel, the server-rendered destination guide explains general fixed-data, hotspot and calling/SMS policies, followed by preparation steps and six native FAQs. The repeated range/count stat cards are removed. `src/lib/destination-content.ts` still derives factual FAQ content and localized metadata from that destination's fixed plans. FAQ operator names are a destination-specific union across variants, explicitly qualified rather than promised for every plan. Regional FAQs direct visitors to the selected plan's exact coverage. This general guidance stays visible when filters have no results.

The layout uses the supplied merchant reference as inspiration for hierarchy only. Copy is original and uses the supplied provider facts. No prices, unlimited-data claims, reviews, savings, guaranteed speeds, invented support availability or real purchase functionality are added. There is no FAQ rich-result promise. Google recommends [helpful, original content for people](https://developers.google.com/search/docs/fundamentals/creating-helpful-content); country names alone are not a substitute for useful country-specific information.

Before a public commercial launch, verify technical conditions with the provider, test the journey on physical iOS Safari and Android Chrome devices, review representative local/regional variants, and confirm the production domain and Search Console indexing setup. Supabase and payment/provisioning remain a later phase.
