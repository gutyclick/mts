# Checkout coupons implementation plan

**Goal:** Editable, auditable promotions and a simpler bilingual checkout in the existing application.

**Architecture:** MyTripSim owns coupon definitions, quotes and locked usage reservations in Supabase. Stripe receives trusted discounted unit prices through the existing checkout path, retaining its existing verification, fulfillment and refund behavior. The admin UI reuses the current admin session and MFA.

**Tech stack:** Next.js, React, TypeScript, Supabase PostgreSQL RPCs, Stripe Elements, PGlite.

## Decisions

Internal coupon RPCs fit the existing locked financial snapshots and per-customer
caps. Stripe-native promotion objects alone would not enforce the supplier margin
guard and guest identity limits. A browser-only discount is unsuitable because it
cannot enforce pricing or usage safely. No catalog prices or historical orders
are changed. Administrative deletion archives the offer; the code stays immutable
to preserve audit meaning. Coupon campaigns are explicit promotional overrides of
the normal 5% reference, still subject to at least 20% contribution. Coupons do
not stack with SimCoins earning or redemption.

The user delegated implementation choices and requested creation, editing, dates,
caps and checkout simplification. Scope includes the additive migration and
production integration; creating an active commercial campaign is a separate
business action. Initial installation creates no live coupons.
