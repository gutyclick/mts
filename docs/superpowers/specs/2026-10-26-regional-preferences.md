# Regional preferences and true multicurrency checkout

User-approved: popup patterned after supplied reference, brand blue/orange rounded UI; only es/en. Currency display AND actual charging in selected currency. Include USD EUR GBP CAD CHF AUD MXN COP ARS CLP DOP UYU BRL KRW CNY JPY PEN DKK. Principal Latin American pesos interpreted as MXN/COP/ARS/CLP/DOP/UYU. No additional language routes.

## Architecture
- Native dialog, language/currency accessible tabs, card selection, close/Escape/focus restoration, responsive. Shared provider above cart, triggers header/footer, required currency-preference persistence only (not analytics).
- Existing base catalog/orders/accounting remain USD for provider fulfillment, existing financial aggregates and backward compatibility. NEW immutable payment snapshot: payment_currency, payment_total, fx_snapshot_id on orders; payment_unit_amount, payment_stripe_price_id on items. Legacy null fields resolve to canonical USD amounts/IDs.
- Source: Stripe FX Quotes API 2025-07-30.preview, to_currency usd, all17 from currencies, lock_duration none. Actual live probe returned200 and all17 currencies (no charge/hold). Use reciprocal base_rate, no MyTripSim FX markup. Do NOT use Adaptive Pricing automatic2–4% surcharge or location-limited currency options. Stripe settlement/processing costs remain business costs; banks may impose their own fees. No claims of guaranteed market rates or zero total fees.
- Cache trusted immutable rate snapshot in protected Supabase table; numeric precision and half-up minor-unit rounding agree in TS/SQL. JPY/KRW/CLP zero decimals, remaining2. Show snapshot time. Refresh hourly via existing signed maintenance machinery or bounded cache refresh with lease; rate validity max24h, require currently issued snapshot for new checkout. Existing attempts retain original amounts/rate even if quote expires; never reprice a prepared payment session.
- Public price-display endpoint projects converted catalog prices or one selected currency quote for storefront use only; never secrets. Quotes endpoint need not expose all raw third-party rates. Server calculates/locks prices from trusted quote and canonical database catalog, rejecting forged local totals/currencies/expired snapshots and preserving original checkout idempotency.
- Validate original USD Stripe prices and product identity. For non-USD use inline price_data for those same existing products with server-calculated local unit amounts. Bind actual generated price IDs after creating session and before returning client secret. Verification uses immutable expected local amounts + IDs, environment, customer/order metadata; no relaxation of total verification.
- Signed webhook records canonical financial status only AFTER validating actual payment snapshot; record_checkout_event_v2 may receive canonical USD snapshot internally to preserve legacy service contract. Payment/expiry/hold inspections use local snapshot. Store original customer-paid currency/amount, never calculate receipt from current FX.
- Refund request computes exact local original unit amounts and currency; claim/execution/reconciliation checks actual PaymentIntent currency and captured amount. Do not reconvert at refund time. Preserve reservation/lease gates, stable idempotency and unknown-outcome safety. Admin refunds show actual currency; base USD analytics labeled as such. Existing USD orders behave unchanged.
- Customer checkout/cart/purchase summary/receipt/wallet consistently show selected or recorded payment currency using correct minor units. SSR SEO price schema stays canonical USD with honest offers. No prices mislabeled as selected currency during rate loading; disable pay until a valid displayed quote is available. Currency changes reset a pending form to details with new explicit total; no automatic confirmation.
- Legal ES/EN update to v3; retain prior acceptance records.
